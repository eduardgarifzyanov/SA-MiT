# Возобновление SSL и производительность

Изменения подготовлены 06.11.2026 после остановки SSL. Полное обучение
автоматически не перезапускалось. Исходный чекпоинт не изменялся.

## Изменения

1. DDP использует no_sync для микробатчей внутри группы накопления;
   forward и backward входят в этот контекст. Последний микробатч группы,
   включая неполную последнюю группу эпохи, синхронизирует градиенты.
   Отключается common.ddp_no_sync=false для диагностики.
2. Сумма train loss накапливается на GPU без графа автодифференцирования.
   CPU получает значение при логировании и в конце эпохи; итоговый loss
   по-прежнему агрегируется между rank. AMP сохраняет проверку пропущенных
   обновлений, clipping и шаги scheduler.
3. persistent_workers и prefetch_factor одинаково применяются в single-GPU
   и DDP. При num_workers=0 persistence выключается и prefetch равен None.
   Настройки по результатам замера: 16 workers/GPU, prefetch=2, persistence=true.
4. История атомарно публикуется после каждой эпохи и включается в checkpoint.
   При resume история checkpoint имеет приоритет перед отдельным JSON;
   это защищает от прерванной записи или от JSON другого момента обучения.
   Старый checkpoint первой SSL-эпохи восстанавливает единственную известную
   train loss из best_value. Для последующих старых эпох значения не выдумываются.
5. Проверена загрузка реального checkpoint: epoch=0, scheduler step=38613,
   LR=0.00011452198192827541, AMP scale=67108864.0. Во всех коротких GPU-прогонах
   выполнены 32 обновления до step=38645; итоговый LR=0.00011446618119932342.
   Loss и веса конечны. Контрольная сумма last.pt до/после одинакова.

## Замер на HDD

Две RTX 6000 Ada, batch=64/GPU, accumulation=2, AMP, исходные PNG на HDD.
Каждый вариант читает отдельные 8192 случайных тайла, всего 32768;
64 микробатча на rank, включая запуск загрузчиков. Выборка индекса seed=810,
перемешивание выбранных путей seed=12. Копий изображений на SSD не создавалось.
Временные индексы, baseline-код и результаты тестовых процессов удалены.

| Вариант | Workers/GPU | Секунды | Тайлы/с |
|---|---:|---:|---:|
| Исходный код | 16 | 70.46 | 116.27 |
| Оптимизированный код | 16 | 70.41 | 116.34 |
| Оптимизированный код | 8 | 76.40 | 107.22 |
| Оптимизированный код | 4 | 94.65 | 86.55 |

Заметного ускорения на HDD не получено. Разница 0.06% между первыми
вариантами неотличима от шума. Оставлены 16 workers; обещать ускорение
эпохи на основе этого замера нельзя. Наборы различаются, влияние кэша и
прочих пользователей хранилища не исключено. Это короткий сравнительный
тест, а не полноценный прогноз времени для 9.9 млн тайлов.

## Проверки и границы восстановления

CPU DDP-тест сравнивает обновления с no_sync и без него, включая unused
параметры и неполную группу накопления; число вызовов коллективных обменов
уменьшается. Отдельный тест AdamW сравнивает обучение без перерыва с
save/load/continue, включая веса, LR, scheduler step и историю. Проверены
ошибки атомарной записи, прерывание следующей эпохи и legacy SSL checkpoint.

Возобновление идёт с границы сохранённой эпохи. Незавершённая часть второй
эпохи не восстанавливается. RNG и очередь prefetched данных не сохраняются:
стохастические аугментации после resume не обязаны побитово повторять
непрерывный запуск. Возобновление с середины эпохи здесь не реализовано.

После проверки изменений запускать из корня проекта в tmux:

```bash
export PATH="/home/user_123/conda/envs/ed_env/bin:$PATH"
export PYTHONPATH="$PWD"
python -m torch.distributed.run --standalone --nproc_per_node=2 \
  scripts/run_pretrain.py --config configs/default.yaml \
  --resume checkpoints/v2/ssl/last.pt
```

При epochs=3 и сохранённой epoch=0 выполнятся оставшиеся две эпохи.
Состав данных, effective batch=256 и параметры loss не изменены.
