# Эксперимент SA-MiT v2

## Данные и воспроизводимость

Конфигурация: configs/default.yaml; подготовка: configs/prepare.yaml.
Нарезка 512×512, шаг 384. Разбиение источников и групп зафиксировано до
нарезки. Используются только подготовленные TSV; READY.json проверяет их SHA256.
Нормализация рассчитана только по train: mean=0.1988170454, std=0.1498203638.
Исходные данные и старые SSL-тайлы не копируются и не меняются.

Доли классов указаны среди валидных пикселей. Ignore — среди всех пикселей тайлов.
Подсчеты взяты из полного аудита подготовки; перекрывающиеся тайлы учитываются
отдельно, как в обучении. SSL: 9887290 тайлов, 4813 источников.

06.11.2026 проверены 72 пары тайл/маска: по 12 разных источников каждого
датасета в каждом split, seed=42. Все изображения и маски размером 512×512;
недопустимых значений классов нет. 12 масок тайлов сверены с преобразованными
срезами исходных масок — совпадают. Контактные листы просмотрены: систематического
поворота или сдвига в этой выборке не обнаружено. Это выборочная проверка,
а не доказательство правильности всех границ и семантики каждого пикселя.
Белый цвет означает ignore. Есть одноклассовые тайлы воды/растительности;
сами по себе они не являются ошибкой разметки.

FUSAR: RGB blue→вода, yellow→дороги, red→строения, green→растительность;
остальное→ignore. OpenEarthMap: water→вода, road→дороги, building→строения,
grass/tree/cropland→растительность, bareland/pavement/background→ignore.
Проверена согласованность с текущим кодом; независимая экспертиза исходной
семантики классов не проводилась.

Пересечений source/group и одинаковых декодированных размеченных исходников
между split аудит не выявил. Географическая независимость OpenEarthMap без
scene-метаданных не доказана; весь SSL-корпус по содержимому не хешировался.
Выборочная проверка test используется только для проверки целостности данных;
по ней не следует подбирать гиперпараметры или менять состав test.

## Обучение

SSL: HOG-MIM, 3 эпохи, batch=64 на GPU, 2 GPU, накопление 2,
эффективный batch=256, AdamW lr=1.5e-4, mask_ratio=0.6, warmup=1500.
SEG: CE + 0.5 Dice, 150 эпох, batch=54 на GPU, накопление 4,
эффективный batch=432 при 2 GPU, lr=6e-5, warmup=1000.
Batch SEG пока не проверен на производственной архитектуре на GPU;
свободная память в SSL не доказывает, что SEG batch поместится.
При изменении batch учитывать также эффективный batch и расписание LR.

Для следующих запусков лог содержит локальный средний loss rank 0, номер
батча, LR, скорость батчей и ETA текущей эпохи каждые 50 батчей.
Эпохальный loss агрегируется между rank. Текущий запущенный процесс новые
изменения не подхватит. Чекпоинты остаются на границе эпохи; безопасное
возобновление с середины эпохи требует отдельной реализации состояния
sampler/RNG/накопления градиентов, здесь оно не добавлено.

## Следующий запуск после освобождения GPU

Не запускать параллельно с текущим SSL. Сначала выполнить короткую GPU-пробу
SEG batch, затем запустить в tmux из корня проекта:

```bash
export PATH="/home/user_123/conda/envs/ed_env/bin:$PATH"
export PYTHONPATH="$PWD"
python -m torch.distributed.run --standalone --nproc_per_node=2 \
  scripts/run_finetune.py --config configs/default.yaml \
  --pretrained checkpoints/v2/ssl/best.pt
```

Загрузка энкодера выполняется strict=True; оценку качества переноса можно
провести только после появления реального SSL-чекпоинта. Обучение использует
train, выбор best.pt — только val mIoU. Test запускать после фиксации модели:

```bash
python scripts/run_infer.py --config configs/default.yaml \
  --checkpoint checkpoints/v2/seg/best.pt --output results/v2/test
python scripts/qualitative_report.py --config configs/default.yaml \
  --checkpoint checkpoints/v2/seg/best.pt --output results/v2/qualitative
```

Существующий Evaluator предоставляет IoU/F1 по классам, pixel accuracy,
матрицу ошибок и kappa. Качественный отчет выбирает типичные и сложные
примеры; это анализ после окончательной оценки, а не основание настройки
модели по test. Сохранить конфиг, git commit/diff, READY.json, checkpoint,
history и результаты для каждого запуска. Старые результаты с утечкой
не считать независимой оценкой. Новых метрик качества обученной v2 пока нет.
