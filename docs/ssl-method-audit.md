# Аудит HOG, маскирования и аугментаций

Проверка 06.11.2026, CPU, фиксированный checkpoint epoch_0000.pt.
Активное SSL-обучение и его целевая функция не изменялись.

## Что проверено

HOG сравнивался с независимым NumPy-расчётом Sobel и гистограмм по ячейкам.
Генератор скрывает 614 из 1024 блоков (59.96%, round от 0.6×1024).
Скрытые значения после маскирования не влияют на вход энкодера; цель считается
по полному изображению после train-аугментаций, до маскирования. Loss и его
градиент учитывают только скрытые ячейки. Карта speckle в модели получает
уже маскированное изображение через тот же вход модели.

Маска заполняется нулём в нормализованных координатах: при обратной
нормировке это средняя яркость train, а не чёрный цвет исходного изображения.
Повороты и отражения сохраняют соответствие изображения и меток, resize
не создаёт новых class IDs. Eval детерминирован. Среднее и дисперсия
гамма-спекла проверены на константном изображении без обрезания диапазона.
Это технические проверки; физическая адекватность всех SAR-аугментаций
и полезность признаков для сегментации ими не доказываются.

## Сравнение с простыми предсказаниями

12 случайных train-тайлов, по 6 разных источников каждого датасета, seed=42.
Сначала фиксируются аугментации и маски seed=100+index. Постоянный вектор
из 27 значений оценивается по первым 6 тайлам; следующие 6 имеют другие
источники. Это небольшая диагностическая подвыборка train, не validation/test.

| Предсказание | Средний MSE на скрытых ячейках последних 6 тайлов |
|---|---:|
| Модель после первой эпохи | 0.0093893 |
| Постоянный вектор из первых 6 тайлов | 0.0210516 |
| Нулевой вектор | 0.8984824 |

Ошибка модели примерно на 55% ниже константы в этом замере. Это аргумент
против полного схлопывания к одному постоянному ответу, но не доказательство
обобщения или пользы SSL для сегментации. Предсказания заметно сглажены;
изображения в results/v2/method_audit показывают полную карту, в loss входят
только белые скрытые ячейки маски. Цветовые шкалы target/pred различаются;
по одной яркости карт сравнивать численные значения нельзя.

## Найденные методические проблемы

1. На нулевом изображении magnitude=sqrt(1e-12)=1e-6. После L1-нормировки
   с epsilon=1e-6 первый нормированный bin равен примерно 0.5, а не нулю.
   Это подтверждённое численное смещение на ровных областях.
2. Нулевой padding Sobel создаёт искусственные границы. Для изображения
   из единиц сумма raw histogram в угловой ячейке 0.4853, во внутренней
   около 1e-6. Следует отдельно сравнить padding и обработку краёв.
3. Среднее беззнакового угла считается линейно, хотя направления периодичны
   с периодом 180°. Равновесные 1° и 179° дают линейные 90°, в то время как
   круговое среднее через удвоенный угол близко к 0°. Текущую величину нельзя
   считать корректным круговым средним ориентации.
4. Третий набор из 9 каналов — девять копий одного значения среднего угла.
   Это не девять независимых признаков. Такой 27-канальный дескриптор является
   собственной конструкцией, а не стандартным block-normalized HOG.
5. На одном проверенном тайле доля нулевых пикселей после train-аугментаций
   выросла с 0 до 31.51%; максимум насыщения в единицу в выборке — 3.03%.
   Нужен отдельный эксперимент с силой радиометрии и clipping; автоматического
   вывода, что выбранные параметры полезны для реального SAR, делать нельзя.

Эти пункты требуют отдельной версии HOG/аугментаций и контролируемого сравнения.
При смене целевой функции новый запуск нужно учитывать отдельно. Значения loss до и после такой смены относятся к разным задачам.
Текущие веса не становятся автоматически бесполезными; решающая проверка —
перенос на сегментацию по сравнению со случайной инициализацией.

## Парное сравнение SEG

В запуске 09.11.2026 сравнили случайную инициализацию энкодера и энкодер
после 4-й эпохи HOG-MIM (файл `checkpoints/v2/ssl/epoch_0003.pt`,
SHA256 `bee634715663f4ccb853c9d75dae6ce0b82efc82fc0fb5f6d28f9ab31a13dd92`).
В обеих ветках обучали весь сегментатор. Голова сегментации начинала с
одинаковых случайных весов. Использовали seed 42 и одинаковые индексы
train, val и test. Подготовленные индексы проверяются через `READY.json`.

Парные конфиги `configs/experiments/seg_ssl.yaml` и
`configs/experiments/seg_scratch.yaml` используют подготовленный датасет на
SSD, batch size 36 на GPU, две GPU и 6 шагов накопления градиентов.
В фактическом запуске с SSL тайлы читались с HDD, а ветка с нуля читала
их копию с SSD. Контрольные суммы индексов совпадают. Для сравнения
скорости сходимости используем эпохи, поскольку носитель у веток различался.

### Запуск

В конфиге `epochs: 150` задаёт горизонт расписания LR. В эксперименте
обе ветки завершили по 52 эпохи с этим расписанием. Приведённые команды
запускают обычный цикл на 150 эпох. Для точного повторения бюджета цикл
нужно остановить после сохранения 52-й эпохи, сохранив горизонт LR.
На сервере ограничение цикла для ветки с нуля записано в
`results/v2/ablation/ssl_ablation_seed42/train.py`. Перед повторным запуском
укажите свежие каталоги чекпоинтов, истории и логов для обеих веток.

```bash
export PYTHONPATH="$PWD"
# С нуля
python -m torch.distributed.run --standalone --nproc_per_node=2 \
  scripts/run_finetune.py --config configs/experiments/seg_scratch.yaml
# С SSL
python -m torch.distributed.run --standalone --nproc_per_node=2 \
  scripts/run_finetune.py --config configs/experiments/seg_ssl.yaml \
  --pretrained checkpoints/v2/ssl/epoch_0003.pt
```

Для теста выбрали лучшую эпоху каждой ветки по `val mIoU`. Скрипт
`scripts/run_scene_eval.py` с `--split test --limit-per-dataset 0` собрал
предсказания по 5 948 тайлам в координатах 663 исходных снимков.
Хеш тестового индекса —
`7f66706197def8b5ab13c01d883da9cadfbafb752ce07fdcd16e22344310209d`.

### Результат

| Метрика | С SSL | С нуля | Разница, п. п. |
| --- | ---: | ---: | ---: |
| Лучший val mIoU | 61,95% (эпоха 35) | 57,98% (эпоха 51) | +3,97 |
| Test mIoU по сценам | 62,89% | 59,99% | +2,89 |
| OpenEarthMap-SAR (651 сцена) | 63,09% | 60,14% | +2,95 |
| FUSAR-Map (12 сцен) | 24,74% | 25,57% | −0,82 |

Разница рассчитана по неокруглённым значениям. С SSL модель достигла
58,31% val mIoU уже на 9-й эпохе. На тесте наибольший прирост IoU получили
дороги (+4,35 п. п.) и строения (+3,67 п. п.). Сравнение выполнено для
одного seed, поэтому разброс между инициализациями пока не оценён.

На сервере сводка с точными метриками и SHA256 обоих SEG-чекпоинтов хранится
в `results/v2/ablation/ssl_ablation_seed42/comparison.json`, рядом лежит
`report.html`. CPU-тесты в `tests/test_ssl_semantics.py` проверяют текущее
вычисление HOG, маскирование, loss и преобразования.
